# 身份生命周期

用户、凭据、账户状态、MFA、Passkey、恢复流程和 group 成员关系均由配置的 OIDC
提供方负责。Lightkite 刻意不提供本地用户管理页面。

登录成功后，Lightkite 仅按标准 `issuer + sub` 保存展示资料，包括展示字段、最后
登录时间、用于平台策略判断的提供方 group，以及 Dashboard 偏好。Group 以 JSON
字符串数组保存，标点符号也会作为 claim 值的一部分被精确保留。该记录不是账户，
无法独立完成认证。从旧版逗号分隔格式升级时会撤销现有会话并停用由这些会话授权
的定时任务；用户重新登录后需要显式重新启用相应任务。

Kubernetes 权限通过原生 RBAC 绑定提供方中的精确用户或 group。Lightkite 自有共享
数据的管理权通过 `PLATFORM_ADMIN_GROUPS` 配置。两条权限边界应始终分开。

删除或停用人员应在身份提供方完成。现有 Lightkite 会话还应通过退出登录或运维会话
清理撤销；提供方 token 刷新与验证会阻止已移除身份建立新的有效会话。
